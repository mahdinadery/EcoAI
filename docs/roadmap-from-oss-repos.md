# راهنمای ایده‌ها از سه ریپوی متن‌باز + لیست کارها

> هدف: **دریافت اخبار یک حوزهٔ خاص (اعتبارسنجی/رتبه‌بندی اعتباری) و انتشار آن در یک کانال (فعلاً بله)**.
> تاریخ: ۲۷ مهر ۱۴۰۵ — وضعیت فعلی محصول: دریافت RSS → فیلتر موضوعی/ممنوعه → تحلیل AI با گیت سخت‌گیرانهٔ
> «اهمیت **و** مرتبط بودن» → ارسال زمان‌بندی‌شدهٔ نیم‌ساعته به بله + داشبورد و تشخیص اجرا.

## ۱) بررسی ریپوها

TypeScript · ~۸۹k ستاره · داشبورد «وضعیت آگاهی» با تجمیع خبر AI، نقشه، پایش زیرساخت.

**ویژگی‌های جذاب و قابل اقتباس:**

| ویژگی | توضیح | ارزش برای ما |
|---|---|---|
| **بولتن‌های AI-Synthesized** | صدها سیگنال را در «Brief» ساختاریافتهٔ چندبخشی خلاصه می‌کند | حالت «بولتن روزانه» به‌جای تک‌پیام |
| **Feed Validation روزانه** | CI روزانه سلامت همهٔ فیدها را چک می‌کند (زنده‌بودن، https، redirect) و خطاها را برای اپراتور اکشن‌پذیر گزارش می‌دهد | دقیقاً درد «فیدها در دسترس نیستند» ما |
| **Variants از یک کد** | چند سایت تخصصی (finance/tech/energy/…) از یک کد | چند «حوزه» (اعتبارسنجی، بیمه، بانکداری) با یک استقرار |
| **همبستگی جریان‌ها** | هم‌گرایی سیگنال‌های نظامی/اقتصادی/حوادث → بالا بردن اهمیت رویداد | خوشه‌بندی خبرهای تکراری از منابع مختلف → «چند منبع تأیید کرد» |
| **Country Instability Index** | شاخص امتیازی زنده با بازه‌ها و تغییر ۲۴ ساعته | الهام برای «شاخص ریسک اعتباری» حوزه |
| **Local AI (Ollama)** | اجرا بدون API Key | پایین آوردن هزینه؛ endpoint سازگار با OpenAI داریم |
| **جست‌وجوی سراسری + لینک اشتراکی** | جست‌وجوی فرمان (Command Palette) و deep-link بازشدنی | جست‌وجوی آرشیو + لینک‌پذیری خبرها در داشبورد |

**چه چیزی را کپی نکنیم:** نقشه‌های ۳D/deck.gl، اپ دسکتاپ Tauri، prediction market، RTL چندزبانه (داریم).

### AgentEra/Agently-Daily-News-Collector — گردآورندهٔ روزانه با خروجی بولتن
Python · ~۶۴۰ ستاره · ورودی: یک موضوع → خروجی: گزارش روزانهٔ Markdown چندستونی.

**ویژگی‌های جذاب و قابل اقتباس:**

| ویژگی | توضیح | ارزش برای ما |
|---|---|---|
| **Pipeline پنج‌مرحله‌ای** | outline → search → shortlist → browse → summarize → نوشتن ستون‌ها | الگوی «بولتن چندستونی» برای پیام بله |
| **گزینش دومرحله‌ای با امتیاز** | هر خبر: `relevance_score` ۰–۱۰ + `recommend_comment` («چرا مهم است») | افزودن فیلد «چرا مهم است» به تحلیل و متن پیام |
| **پرامپت‌های YAML ویرایش‌پذیر** | پرامپت‌ها جدا از کد و در `prompts/*.yaml` | «قالب‌های پرامپت آماده» در پنل (پیش‌فرض‌های حوزه‌ای) |
| **جست‌وجو + مرور وب برای پوشش** | وقتی خبری نبود، با Search ابزار و مرورگر (Playwright) شکاف را پر می‌کند | **پرکردن شکاف پوشش**: وقتی فیدها خبر حوزه نداشتند، جست‌وجوی هدفمند |
| **تفکیک tools / workflow / prompts** | لایه‌بندی تمیز | الگوی معماری (بخشی را داریم) |

**چه چیزی را کپی نکنیم:** پشتهٔ Python/Agently (ما Next.js هستیم)، خروجی PDF/Markdown فایل‌محور (ما DB و بله داریم).

### vinay-gatech/stocks-insights-ai-agent — RAG عاملی روی اخبار + داده‌های مالی
Python · ~۷۵۰ ستاره · LangChain/LangGraph/ChromaDB/MongoDB/Postgres.

**ویژگی‌های جذاب و قابل اقتباس:**

| ویژگی | توضیح | ارزش برای ما |
|---|---|---|
| **تمرکز بر موجودیت (per-ticker)** | اخبار هر سهام/شرکت جدا جمع و تحلیل می‌شود | **پروندهٔ ناشران/بانک‌ها**: «هر آنچه این هفته دربارهٔ بانک X» — ایدهٔ طلایی برای مخاطب اعتبارسنجی |
| **Retrieval Grader (بله/خیر)** | یک گریدر ارزان، مدرک بازیابی‌شده را از نظر مرتبط بودن نمرهٔ دودویی می‌دهد | «گرید دومرحله‌ای» برای خبرهای مرزی (امتیاز ۵۵–۷۰) |
| **آرشیو برداری + جست‌وجوی معنایی** | MongoDB → ChromaDB، جست‌وجوی معنایی روی اخبار | اخبار مرتبط قبلی، پیگیری رویداد در طول زمان، تشخیص تکرار بهتر |
| **Web-search fallback** | اگر سند مرتبطی در DB نبود → جست‌وجوی وب | مکمل «شکاف پوشش» (با Agently) |
| **NL→SQL + نمودار** | پرس‌وجوی طبیعی از داده‌های مالی | فعلاً خارج از دامنه (دادهٔ مالی نداریم) |

**چه چیزی را کپی نکنیم:** پشتهٔ LangGraph، اسکرپ مالی/سهام، MongoDB (ما Postgres/Drizzle داریم).

## ۲) شکاف محصول ما در برابر این ایده‌ها

پایه (دریافت → فیلتر → تحلیل AND → ارسال نیم‌ساعته → داشبورد/تشخیص) **کامل است**. آنچه کم داریم:

1. **پوشش**: اگر فیدها خبر حوزه نداشته باشند، چیزی نمی‌فرستیم (درست) ولی شکاف را هم پر نمی‌کنیم.
2. **سلامت فیدها**: درد کهنهٔ «فید در دسترس نیست» را فقط دستی می‌بینیم.
3. **فرمت انتشار**: فقط تک‌خبر؛ بولتن نداریم.
4. **عمق**: موجودیت‌ها (بانک/ناشر) استخراج نمی‌شوند؛ آرشیو جست‌وجو/پیگیری ندارد.
5. **چندحوزه/چندمقصد**: یک حوزه + یک مقصد (ارسال چندگانه پیشنهاد شده ولی ساخته نشده).
